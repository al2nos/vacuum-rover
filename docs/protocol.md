# Протокол обмена данными (MQTT)

Транспорт — MQTT 3.1.1. Брокер: mosquitto на VDS `10.77.0.1:1883`
(доступ только из VPN 10.77.0.0/24, логин/пароль на узле).
Для браузера брокер слушает WebSocket `127.0.0.1:9001` (через nginx).

## Топики

| Топик | Направление | QoS | Retain | Содержимое (JSON) |
|---|---|---|---|---|
| `rover/<node>/telemetry/system` | узел → все | 0 | нет | `{"cpu": %, "mem": %, "temp": °C, "uptime": ч, "ts": epoch}` |
| `rover/<node>/telemetry/lidar` | узел → все | 0 | нет | статистика: `{"speed_hz": , "rpm": , "packets_ok": , "packets_bad": , "frames_meas": , "scan_age": }` |
| `rover/<node>/telemetry/lidar` | узел → все | 0 | нет | **скан:** `{"start": °, "step": °, "rpm": , "r": [мм,…]}` — см. ниже |
| `rover/<node>/status` | узел (LWT) | 0 | **да** | `online` / `offline` (last will) |
| `rover/<node>/cmd/teleop` | пульт → узел | 0 | нет | `{"vx": м/с, "wz": рад/с, "ts": epoch}` |
| `rover/<node>/config` | узел → все | 0 | **да** | текущий конфиг узла (любой JSON) |
| `rover/<node>/config/set` | пульт → узел | 0 | **да** | новый конфиг; узел применяет и публикует в `config` |

`<node>` = имя узла: `tinker`, `opi3`, `zero2w`…

## Сканы лидара (карта)

Оба подтипа сообщения идут в один топик `telemetry/lidar` и
различаются наличием поля `r`. Скаляры (`rpm`, `rate_hz`, потери) —
раз в секунду; скан — с частотой вращения (~6–8 Гц).

```json
{
  "start": 0.0,      // угол первого луча, градусы (0 = вперёд)
  "step": 1.0,       // шаг между лучами, градусы
  "rpm": 352,        // скорость вращения (необязательно)
  "r": [1250, 0, 4300, …]   // 360 дистанций в миллиметрах; 0 = нет отражения
}
```

- Система координат скана: 0° — направление вперёд ровера, угол
  растёт против часовой стрелки (вид сверху). Декодеры kaiaai/LDS
  отдают именно так.
- Полный оборот = 360 лучей при `step: 1.0`. Delta-2C PRO отдаёт
  360 точек/оборот с разрешением 0.25 мм — значения в `r` округляем
  до миллиметров.
- Консоль сканы **не пишет в SQLite**: хранит последний, считает
  частоту (scans/s) и шлёт в браузер по WebSocket (`{"type":"scan",…}`,
  троттлинг ~8/с). В SQLite остаются только скалярные метрики.

## Мост «декодер → консоль» на узле

Агент узла (`deploy/node-agent/agent.py`) пробрасывает сканы от
локального декодера `deploy/node-agent/lidar_delta.py`: декодер пишет JSON
со сканом в файл `$ROVER_SCAN_FILE` (по умолчанию `/run/rover/scan.json`),
агент при изменении файла публикует его в `telemetry/lidar` (опрос 20 Гц,
публикация до ~8/с). Скалярная статистика пишется декодером в
`$ROVER_LIDAR_STATS` (`speed_hz`, `rpm`, `packets_ok`, `packets_bad`,
`frames_meas`, `frames_speed`, `scan_age`) и публикуется раз в секунду.
Телеметрия системы и телеуправление работают независимо от лидара.

## Границы с ROS 2 / Nav2 (этап 3)

Этот протокол — канал устройств и мониторинга, он не заменяется ROS 2.
Распределение каналов жёсткое:

- **MQTT (этот документ)** — телеметрия, сканы, статус, телеоп-резерв,
  конфиги. Всё, что должно работать на любом железе и за NAT.
- **ROS 2 Jazzy** — бортовой автономный стек на Tinker Board 2:
  LaserScan, tf, slam_toolbox, Nav2, `/cmd_vel`. Внешнего доступа
  не имеет, кроме rosbridge.
- **rosbridge** — WebSocket-JSON поверх ROS 2 на Тинкере (порт 9090);
  nginx на VDS проксирует `/rosbridge/` → `ws://10.77.0.11:9090`.
  Через него пульт получает `/map`, `/amcl_pose`, `/plan` и шлёт
  цели (`/navigate_to_pose`), рендер — roslibjs в браузере.

Правило: карты/пути/costmap через MQTT не гонять (объём, частота),
мониторинг через rosbridge не дублировать. Base controller на ровере
слушает `/cmd_vel` (Nav2) и `cmd/teleop` (MQTT) с приоритетом
автономки и общим watchdog 0.5 с.

## Соглашения

- Телеметрия системы: **1 Гц**. Телеметрия лидара: 1 Гц (агрегаты) +
  сканы с частотой вращения.
- Все временные метки — Unix epoch (секунды, float).
- `ts` в телеметрии — время замера на узле; брокер не подменяет.
- LWT: при подключении узел публикует retained `online` и регистрирует
  will `offline` — пульт так определяет живость узла.
- Конфиг — единственный retained-канал управления: узел при старте
  читает `config/set`, применяет, публикует результат в `config`.
- Телеуправление: `vx` — линейная скорость (м/с, + вперёд),
  `wz` — угловая (рад/с, + против часовой). Таймаут безопасности на
  узле: 0.5 с без пакетов → стоп.

## Пульт

Веб-пульт: `https://3dlb.ru/console/` (логин/пароль сайта).
Сервис `rover-console` на VDS: FastAPI + SQLite + WebSocket,
подписка на все топики `rover/#`. API:

- `GET /api/nodes` — узлы, живость, метрики, активность
  (`sys_hz`, `lidar_hz`, `scan_points`, `scan_age`)
- `GET /api/history?node=&metric=&minutes=` — история из SQLite
- `GET/POST /api/config/<node>` — чтение/запись конфигурации
- `WS /ws` — live-поток метрик и сканов + приём команд телеуправления

Экран пульта: карточки узлов · графики по каждому датчику (30 мин +
live) · **карта лидара** (последние сканы, вид сверху, след затухает) ·
**активность датчиков** (msg/s по источникам, возраст скана) ·
джойстик телеуправления · редактор конфигурации · журнал.

## Доступы (хранятся на VDS, НЕ в репозитории)

- `/etc/mosquitto/passwd` — пользователи брокера (root:mosquitto, 640)
- узлы: `tinker`, `opi3`, … ; сервисы: `console`, `agent`
- Пароль консоли: `/opt/rover-console/.env` (`ROVER_MQTT_PASS`)
- Пароли выдаёт владелец или генерирует агент с доступом к VDS;
  в репозиторий — не коммитить. После смены пароля в passwd —
  `systemctl restart mosquitto`.
