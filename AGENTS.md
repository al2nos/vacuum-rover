# AGENTS.md — правила работы ИИ-агентов в проекте

Этот репозиторий ведут сменяющие друг друга ИИ-агенты под контролем человека
(владелец: al2nos). Агенты взаимозаменяемы: любой агент выполняет любую
роль — в зависимости от того, какой агент доступен владельцу. Документ —
обязателен к прочтению перед первым действием.

## Проект в двух абзацах

4WD-ровер из двух роботов-пылесосов (Mi Robot Vacuum-Mop P STYTJ02YM +
Mijia 3C Enhanced C103). Привод: 4 колёсных модуля от пылесосов, скид-стир,
2 × BTS7960. Мозг — Tinker Board 2 (лидары Delta-2A/2C PRO, стереозрение,
ROS 2). Второй одноплатник — телеуправление. Рама печатается на FF AD5X.
Подробности — в `docs/`.

## Порядок онбординга (строго в этом порядке)

1. Этот файл (AGENTS.md)
2. `docs/STATE.md` — текущее состояние, что сделано, что заблокировано
3. `docs/roadmap.md` — чек-лист, этапы, бюджет
4. Разделы `docs/` по текущей задаче
5. Открытые issues — свободные задачи и задачи «в работе» с эстафетой

После онбординга агент в первом комментарии/PR пишет: какую задачу берёт
и под какой ролью работает.

## Роли — это шапки, а не личности

Роли функциональные, их надевает любой агент на время задачи:

- **Navigator** — архитектура, решения, интеграция узлов
- **Mechanic** — CAD/3D-печать рамы, крепления, замеры
- **Driver** — софт: моторы, энкодеры, лидара, ROS 2, телеуправление
- **Scout** — исследования: даташиты, распиновки, протоколы, сравнения

Один агент = одна активная задача. Агент может сменить роль между
задачами, но не в середине — тогда сначала эстафета (ниже).

## Протокол передачи эстафеты (ключевой)

Любой агент может закончиться (лимит токенов, смена модели). Каждая
сессия обязана заканчиваться записью в issue задачи:

```
## Handoff (агент <имя>, <дата>)
- Сделано: ...
- Текущее состояние: ...
- Следующий шаг: ...
- Файлы/ветка: ...
- Предположения: ...
- Блокеры: ...
```

Следующий агент начинает с чтения последнего Handoff — и продолжает
без потери контекста. Нет Handoff = сессия не завершена.

## Правила взаимодействия

1. **Задача = issue.** Перед стартом: взять issue (свободное или эстафету),
   написать комментарий «беру, роль X». Никакой работы «вникуда».
2. **Ветка на задачу**: `task/<краткое-описание>` от `main`
   (код и CAD). Документацию можно коммитить напрямую.
3. **Коммиты**: conventional style (`feat:`, `fix:`, `docs:`, `cad:`,
   `test:`), на русском, кратко. В конце сообщения трейлер
   `Agent: <самоназвание агента>` (имя даёт владелец или агент выбирает).
4. **PR вместо прямых пушей** в `main`/`rover-a` для кода и моделей.
   Перед PR — rebase на свежий `main`.
5. **STATE.md обновляется при любом изменении статуса** — главный канал
   синхронизации между сменами агентов. Забыл обновить STATE.md =
   задача не сдана.
6. **Спорные решения** — обсуждение в issue/PR, финальное слово за
   человеком. Не переписывать чужие решения молча.

## Границы (только с подтверждением человека)

- Удаление веток, репозиториев, файлов из `main`
- Force-push в любую общую ветку
- Изменение архитектурных решений (состав плат, распределение узлов)
- Закупки/списание бюджета (метка `needs-human`)
- Мердж в `main` (через PR + аппрув человека)

## Правила честности (критично для железа)

1. **Никаких выдуманных замеров и распиновок.** Если данных нет —
   ставим `TODO(needs-measure)` и открываем issue человеку. Угаданная
   распиновка = сгоревший GPIO.
2. Предположения помечаем явно: «предположение: …», и проверяем их
   первыми.
3. Утверждение «готово» = есть доказательство: вывод теста, фото,
   лог запуска. Не «должно работать», а «проверено, вот вывод».
4. Внешние факты (даташиты, протоколы) — со ссылкой на источник
   в комментарии или docs.
5. Физические константы проекта (масса, размеры, токи) храним
   в `docs/` один раз, все агенты берут оттуда, не дублируют.

## Код и модели

- Код: Python 3, ROS 2 Jazzy, комментарии и идентификаторы на английском,
  документация на русском.
- CAD: OpenSCAD (параметрические модели), STL рядом, параметры — в шапке
  .scad, чтобы любой агент мог перегенерировать.
- Печать: PETG/TPU 95A, настройки из `docs/frame-print.md`.
